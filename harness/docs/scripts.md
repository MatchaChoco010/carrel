# エージェント向けスクリプトと一時検証スクリプトの扱い

このドキュメントは **スクリプトを書く/置く場所を決めるときに読む**。

## 再利用するスクリプトは二層に置き、Node.js で書く

AI エージェントが使う skill やハーネスの**再利用**スクリプト(skill のフックやヘルパーを含む)は、次の二層のどちらかに置く。

- **共有スクリプト**(どのプロジェクトでも同じもの)→ `harness/scripts/`(共有ハーネスリポジトリで管理し、各プロジェクトへベンダーコピーされる)。
- **プロジェクト固有スクリプト**(プロジェクトの事実に依存するもの)→ プロジェクトの `scripts/`。

どちらに置くかの判断は [editing.md](editing.md)「共有ハーネスかプロジェクト固有かの判断」に従う。
消費側プロジェクトの `harness/scripts/` はベンダー領域なので直接編集しない(変更は共有ハーネスリポジトリへの Issue + PR)。

いずれの層も **Node.js** で実装する。
Python だとグローバルにパッケージを入れられず `.venv` を毎回 activate する必要があるが、Node なら `package.json` と `node_modules/` を置いておけば activate 不要で即実行できる。
Windows(PowerShell 主体)でも摩擦が少なく、エージェントの hook も JS/TS 系で一貫する。
`jq` や `python3` への依存は、環境によって(とくに Windows)不在・破損するため避ける。
**スクリプトは Node で揃える。**

skill に同梱するフックスクリプトのように、特定 skill に強く結びつくものは、その skill 配下(skill ディレクトリの `scripts/`)に併置してよい。
その場合も Node で書き、純 Node stdlib(依存ゼロ)に保って OS 非依存にする。

## 一時的な検証スクリプトはリポジトリに残さない

動作確認や調査のためにその場で書く**使い捨てスクリプト**は、リポジトリにコミットしない。
**スクラッチパッド(セッション専用の作業ディレクトリ)** などリポジトリ外で書いて使い、終わったら捨てる。
リポジトリに置いてよいのは「何度も使う」と確信できるものだけで、その場合は再利用手段(README・呼び出し元 skill)ごと上記の二層のどちらかに整備する。

一時検証スクリプトと再利用スクリプトを混同しない。
判断基準:

- アサーション(期待値の機械判定)が無く、出力を人間/エージェントが目視で確かめるだけ → 一時検証。リポジトリに残さない。
- 回帰を継続的に守る必要があるもの → 一時スクリプトではなく**プロジェクトのテストスイート**に入れる。
- 何度も繰り返すワークフローの手順 → 再利用スクリプトとして Node で整備する。
