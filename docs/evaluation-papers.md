# 変換と照合の評価に使う論文

変換器・モデル・reasoning effort を選び直すときに使う論文の一覧。
Codex に新しいモデルが増えたときや、変換器を更新したときに、この一覧で比べる。

検証の仕組みは残していない。
必要になった時点でスクリプトを書けばよく、仕組みを維持する手間のほうが大きいためである。
残す価値があるのは**どの論文が何を試すか**という知識のほうで、それがこの文書である。

## 何を測るか

### 機械的に測れるもの

**文字の欠落。** PDF の文字層と変換結果・照合結果を文字単位で突き合わせる(0009)。
測るときの注意は次のとおりで、どれも実際に誤った測り方をして気づいたものである。

- ページ単位で測る。ブロックの領域はそのブロックの内容と 1 対 1 に対応しない。
- 数式用の英数字(`𝑀` は U+1D440)は普通の英数字へ均してから比べる。均さないと、正しく LaTeX へ変換できている数式がまるごと欠落として数えられる。
- 変換結果の置換文字(U+FFFD)は、量にかかわらず変換器が文字を落とした印である。

**翻訳の契約。** 数式・図の参照・リンク・見出しの階層が原文と一致するか(0004)。
数式が `$$` で囲まれていないと 1 つも数えられないので、囲まれていることを先に確かめる。

### 機械的には測れないもの

**構造が紙面どおりか。** これは削減率では測れない。
実際、3DGS の 11 ページでは、構造の変更点が最も多い構成(47 件)が削減率では最も低い(53%)という食い違いが出た。

ページ画像と markdown を並べて、次を目で確かめる。

- 紙面にある段落・見出し・表・キャプション・脚注が markdown にあるか
- 2 段組みの読み順、表の行と列、見出しの階層、擬似コードの字下げが紙面どおりか
- 紙面に無い内容が足されていないか(図の中身が文字に起こされていないか)
- 著者名・数値・引用番号が原文どおりか

## これまでに分かっていること

**変換器**: Marker の `fast` モードを GPU で使う(0008)。
MinerU は ACM TOG の組版で本文の文字を落とす。
Marker の `balanced` は遅く、図表とキャプションの分類が失われる。

**照合**: 向きの表(0009)に加えて、探すべき構造の崩れをシステムプロンプトに列挙する必要がある。
列挙しないと、重点的に見る指示が付いたときに注意が文字へ偏る。

**翻訳**: model と effort による速度差が無い。訳文の生成が時間を占めるためである。
`gpt-5.6-sol` の `low` が訳語の一貫性で優る。`gpt-5.6-terra` は訳語が揺れ、`Gaussian` を「ガウス分布」と誤訳した。

## 比べ方の目安

論文ごとに、本文のあるページを欠落の多い順に 3 ページほど選べば傾向は出る。
全ページを回す必要は無い。

Codex の枠は、照合 1 ページで週次枠の 0.03% ほどである。
数百回まわしても枠には届かない。
並行度は 4 まで確かめてある(応答の取り違えは起きない)。
